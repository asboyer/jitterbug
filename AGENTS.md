## The idea

In an ever evolving world where AI capabilities are scaling, this means development is scaling. Yet we are all on the same laptops and compute has never been more expensive. Working on parallel tasks is all fun and games until you are out of memory, your laptop is melting your lap it's so hot, and the fans are louder than a hiss.

Agentic engineering is supposed to be the next layer of abstraction, yet we still need to "manage our memory": watch the resources on our computer, keep an eye on Activity Monitor. But if we've abstracted the layer of knowing every process that's going on, how can we look at 5 different Python processes all at 100% usage and determine what is actually happening? Don't even start about running local models: how in the world do I know what model my computer can handle?

Introducing Jitterbug: an always-on, resource-efficient agent (that uses local models or bring your own API key) to reason through the different processes on your computer, help when your computer is struggling, offload resources, propose efficiency gains, and give you insight into what is actually using resources and why.

## Technical direction

Build a small Tauri desktop app: shared Rust collection, attribution, pressure detection, policy, and provider logic; a TypeScript UI; and explicit macOS/Windows adapters. Start with a live workload dashboard and a contextual assistant. Use deterministic rules first, then interchangeable decision, cheap, and intelligent model tiers through local or cloud providers. Default intelligent work to Meta; reserve local inference for tiny models and easy tasks, with memory/thermal guards, one request at a time, and immediate unloading. Enforce hybrid, local-only, and cloud-only modes before inference. Keep model calls event-driven, history bounded, and resource overhead measurable. Run the native incident loop from detection through intelligent investigation, policy-limited proposal, permitted action, and fresh verification. Automatic actions require a saved per-workload priority permission; never automatically stop processes. Recheck current triggers and permissions at execution, verify OS priority, and distinguish observed changes from causal improvements. Validate process actions against fresh process identity; models never execute arbitrary commands. Label real telemetry, inferred explanations, and demos clearly. TypeScript house style: four spaces, semicolons, single quotes, ES5 trailing commas, 100-column lines, and parenthesized arrow parameters; use the checked-in Prettier configuration. Use conventional commits and push verified milestones to master. This repository is public: never commit secrets, machine details, process snapshots, transcripts, or private runtime data. Store credentials outside tracked files and enforce cloud spending limits.
